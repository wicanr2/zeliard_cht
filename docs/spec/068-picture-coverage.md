# 片頭與結局插畫的HD覆蓋修正

狀態：開發完成、限定驗證，2026-10-23；使用者決定只commit推送，不打包。使用者在1.0.7推送後要求修正結局，以及片頭陽台插畫柱底的棋盤格。

## 原因

已證實，四個原因各自造成插畫局部或整張顯示原版：

| 現象 | 原因 | 證據 |
|---|---|---|
| 陽台插畫左柱底一格棋盤格；國王擁抱圖、Garland離城圖邊緣成鋸齒或身上有原版色塊 | 050人工圖格（[hd_manual_art.py](../../tools/hd_manual_art.py)的`add_tiles`）只收三色以上的8×8格。兩色抖色格沒有HD，原版露出；柱底那格是119／112交錯 | 陽台在74張截圖中該格內容固定，上下左右四格都有登錄，只有這格沒有；跳過的兩色格陽台56格，與1.0.7正式版外露的56格相同 |
| FIN兩張整張原版 | `end7`與`fin`登錄點陣第0列有17／0／1色，實機第0列全黑，整張比對永遠失敗 | 兩張實機截圖第1到133列逐點相同，差異只在第0列 |
| 製作名單中公主日景圖整張原版 | 騎士圖`end4`蓋住公主圖`end6`右下，公主圖可見部分80%相符；片段的母圖上下文守衛要求可見部分全部相符 | 1016M截圖：`end4`在(132,20)相符99.8%，`end6`在(0,0)相符80.0% |
| 守護精靈（片頭732M以後、結局386M）整張原版 | `pictures.json`的`sei`點陣色號解碼錯誤，每個半位元組換位（8→5、C→4、A→1），人工圖格全部對不上 | 換算後與實機截圖14976點全部相同 |

## 處理

- [hd_picture_complete.py](../../tools/hd_picture_complete.py)：把只有人工圖格的插畫補登錄為完整插畫（`complete-art.json`）的整張插畫與8×8片段，兩色格也收，單色格不收。圖面是同一張story圖集的同一次裁切，工具逐格核對既有人工圖格的像素相同。每張插畫的原生點陣須與實機截圖逐點相同才登錄，截圖存在`workplace/picture-coverage-v1/evidence/`，群組記錄截圖與SHA。(../../tools/hd_complete_register.py)會從頭重寫`complete-art.json`，重跑它之後必須以相同參數再跑本工具；參數見WORKLOG。
- 同一工具遮去`end7`、`fin`的第0列（整張與第0列片段），須與實機截圖第1列以後逐點相同。
- 國王擁抱圖`new2`只有112×100，原版洋紅底色佔滿整個框；整張HD接上後，HD圖的背景色在洋紅底色中成為一塊矩形。以`--transparent new2=51`把與圖框邊緣連通的51號點（3,040點中的3,039點）設為透明，背景維持原版，人物用HD。
- [complete_art.go](../../internal/prototype/hd/complete_art.go)：片頭／結局模式（`FF77`非零）時，片段只負責定位母圖。母圖可見部分的特徵點過半與畫面相同、且相同的特徵點至少256點時，依母圖8×8格線畫出：整格逐點相同的格整格畫；與這些格相鄰的交界格只畫逐點相同的非黑色點；其餘格維持原版。特徵點是黑色與母圖最常見兩種非黑色（多半是背景）以外的點。只計總點數時，大半是黑色的魔王雙眼圖`dmaou-cycle-all`在守護精靈與魔王雙眼這類全黑底畫面上有十幾個位置「過半相符」；只排除黑色時，Garland離開後的`ne80`只剩背景兩種抖色相符（非黑色點49.9%、特徵點0%），HD背景格會帶出人物輪廓的殘影。被另一張圖蓋住的公主日景特徵點相符80.8%，片頭公主說話時被雙眼框蓋住為85.9%。局部母圖排在完整插畫與說話沿用之後，只補還是原版的點。片段登錄時已去重，同樣點陣只登錄首見位置，換位置的格無法靠片段本身補滿，所以由母圖畫。遊戲中維持母圖可見部分全部相符，且不出現局部母圖。同一次比對中每個母圖位置只核一次。

## 合成成本

片頭與結局每次畫面改變都要重新比對整幅。補登錄後的第一版每次比對約0.4秒：兩色抖色片段在畫面上到處都對得上，每個巧合位置都完整掃描整張母圖；同一張母圖也在上百個錯位位置被當成局部母圖。現行做法：

- 先嚴格核對（第一個不同就停），完全相符的母圖不再找局部。
- 只有三色以上的片段拿來定位局部母圖。
- 抽樣最多512個特徵點，抽樣相符不到一半、或比目前最佳位置低0.1以上，不做完整核對。
- 每張母圖最多一個局部位置，取特徵點相符比例最高者。
- 放置範圍完全在畫布內時直接讀寫`Pix`；`TestCompletePaintDirectEquivalent`以三張實機截圖核對與原本`RGBAAt`／`SetRGBA`路徑整幅逐點相同。

`BenchmarkPictureCoverageDraw`以同一張實機截圖每次重新比對，`nostory`移除`story-`群組並關閉片頭模式，近似補登錄前；兩者在同一場景交錯執行。主機另有其他專案負載，7次中位數：片頭公主特寫14→17ms、片頭公主說話15→20ms、Ada洞窟26→23ms（雜訊範圍內，遊戲中沒有增加）。

## 未處理

- `sei`：點陣可以換算修正，但HD圖面是依錯誤解碼的參考圖畫的，為黑髮、白披風、紅內襯；實機是青色頭髮、綠色披風、藍色內襯。沒有登錄，維持原版。
- `nec`、`ttl1`、`ttl3`、`yuu1`、`yuu2`在兩次探針中沒有出現，原生點陣未經實機核對，維持人工圖格。
- Garland離開後的空背景（716M到806M）：`ne80`只剩背景兩種抖色相符（特徵點0%），不當成局部母圖，維持原版藍色抖色。Garland在場時，`ne80`圖框外的同色背景仍是原版抖色，與HD背景交界有一條細縫。
- 結局第一段對話（116M到236M）的公主人像：`pictures.json`的`new1`解碼錯誤（參考圖是亂碼），沒有HD圖面；1.0.7起依規格067整框顯示原版，本次不變。
- 片頭公主說話時疊上的魔王雙眼框（468M到524M）與單獨的魔王雙眼（532M到588M），以及插畫之間的空框（404M）：1.0.7即為原版，不在本次範圍。

## 色序

已證實，story圖集與完整插畫圖集的參考圖用了與實機不同的色序：實機片頭（62M）與結局（656M）在下列色號共用同一份色盤，參考圖則紅綠兩色版互換。

| 色號 | 實機 | 參考圖 |
|---|---|---|
| 2、32 | (125,0,0) 暗紅 | (0,127,0) 暗綠 |
| 34 | (251,0,0) 紅 | (0,255,0) 綠 |
| 51（結局） | (251,0,251) 洋紅 | (0,255,255) 青 |
| 98 | (251,125,0) 橘 | (127,255,0) 黃綠 |

實機的低四位元順序是藍、紅、綠（1藍、2紅、4綠），與PC-98數位八色相同；參考圖用的是IBM的藍、綠、紅。強推論：實機是原版色彩，人物膚色用的98號在實機是橘色、在參考圖是黃綠色。HD圖面因此有紅綠互換：陽台公主的裙子實機暗紅、HD綠色；結局Garland實機紅髮紅衣、HD綠髮綠衣；國王擁抱圖背景實機洋紅、HD青色。原貌中文版顯示實機色彩，不受影響。使用者決定（2026-10-23）之後以正確色序重畫，本規格不改動圖面。
