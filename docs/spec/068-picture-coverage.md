# 片頭與結局插畫的HD覆蓋修正

狀態：開發完成、限定驗證，2026-10-23；只commit推送，不打包。使用者在1.0.7推送後要求修正結局，以及片頭陽台插畫柱底的棋盤格；查出插畫HD紅綠色序與原版相反後，要求以正確色序重畫，由Codex內建生圖處理。

## 原因

## 處理

### 補登錄與局部母圖

- [hd_picture_complete.py](../../tools/hd_picture_complete.py)：把只有人工圖格的插畫補登錄為完整插畫（`complete-art.json`）的整張插畫與8×8片段，兩色格也收，單色格不收。每張插畫的原生點陣須與實機截圖逐點相同才登錄，截圖存在`workplace/picture-coverage-v1/evidence/`，群組記錄截圖與SHA。點陣解碼錯誤的`sei`、`new1`、`dmaou`以實機截圖的點陣為準（`--raster-from-dump`）。[hd_complete_register.py](../../tools/hd_complete_register.py)會從頭重寫`complete-art.json`，重跑它之後必須以相同參數再跑本工具；目前參數存在`workplace/picture-coverage-v1/supplement-args-v6.txt`。
- 同一工具遮去`end7`、`fin`的第0列（整張與第0列片段），須與實機截圖第1列以後逐點相同。
- 國王擁抱圖`new2`只有112×100，原版洋紅底色佔滿整個框；整張HD接上後，HD圖的背景色在洋紅底色中成為一塊矩形。以`--transparent new2=51`把與圖框邊緣連通的51號點（3,040點中的3,039點）設為透明，背景維持原版，人物用HD。
- [complete_art.go](../../internal/prototype/hd/complete_art.go)：片頭／結局模式（`FF77`非零）時，片段只負責定位母圖。母圖可見部分的特徵點過半與畫面相同、且相同的特徵點至少256點時，依母圖8×8格線畫出：整格逐點相同的格整格畫；與這些格相鄰的交界格只畫逐點相同的非黑色點；其餘格維持原版。特徵點是黑色與母圖最常見兩種非黑色（多半是背景）以外的點。只計總點數時，大半是黑色的魔王雙眼圖`dmaou-cycle-all`在守護精靈與魔王雙眼這類全黑底畫面上有十幾個位置「過半相符」；只排除黑色時，Garland離開後的`ne80`只剩背景兩種抖色相符（非黑色點49.9%、特徵點0%），HD背景格會帶出人物輪廓的殘影。被另一張圖蓋住的公主日景特徵點相符80.8%，片頭公主說話時被雙眼框蓋住為85.9%。局部母圖排在完整插畫與說話沿用之後，只補還是原版的點。片段登錄時已去重，同樣點陣只登錄首見位置，換位置的格無法靠片段本身補滿，所以由母圖畫。遊戲中維持母圖可見部分全部相符，且不出現局部母圖。同一次比對中每個母圖位置只核一次。

### 正確色序重畫

- 參考圖：[hd_picture_refs.py](../../tools/hd_picture_refs.py)從實機截圖裁出插畫的原生點陣與當時色盤，依既有圖集格位重組1536×1024參考圖，點陣須與登錄來源逐點相同。沒有實機截圖的插畫才用修正後的公式色盤，收據標為未經實機核對。不在任何圖集、或改以實機點陣重新登錄的插畫（`new1`、`dmaou`）以`--single`自成一張，格位寫入`refs.json`，登錄時以`--extra-cells`讀取。
- 生圖：Codex CLI 0.163.0的`codex exec`內建生圖，每張參考圖一次。提示詞要求保留畫布、格位、構圖與人物姿勢，並逐項寫明實機顏色；風格參考是已通過的v2圖面。提示詞、請求、事件紀錄與輸出在`workplace/picture-coverage-v1/generated-v2/`。
- 色相閘門：[hd_hue_check.py](../../tools/hd_hue_check.py)把生成圖依登錄裁切縮成插畫的3倍，每個原生色號取對應3×3點的平均色，與實機色盤比較色相。只比飽和度足夠的色號，以點數加權；加權平均不超過25度、佔5%以上的色號不超過60度。紅綠互換約差120度，暗綠草地畫成橄欖色約差45度。另以亮度位移相關檢查對位，最佳位移須為(0,0)；以4×4原生區塊查灰階，實機區塊是中性灰（純黑除外）而HD區塊彩度超過0.3者須少於5%。逐色號查灰階會把抖色混合與黑色描線畫成陰影都算錯，所以改用區塊平均。
- 登錄：`hd_picture_complete.py`以`--sheet-art`換story圖集，同一插畫須同時`--retile`，把首見位置的8×8人工圖格換成新圖面，舊圖格與清單備份在`workplace/picture-coverage-v1/tile-backup-v1/`。`--replace-art`換完整插畫圖集，只換PNG與SHA；`--keep dmaou`保留不會在實機出現的舊`dmaou`項目；`--composite fin=end7`與`yuu3-final=yuu3-base`讓只差局部的兩張在差異範圍外擴2點以外共用基底圖面，切換時畫面不跳。

### 說話嘴型、眨眼與換色畫格

[hd_portrait_patch.py](../../tools/hd_portrait_patch.py)處理只在局部與底圖不同的畫格。以實機色盤比較每個畫格與底圖點陣的顏色，顏色不同的點外擴1點為重畫範圍；參考圖在範圍內貼原版點陣的實機色，四周保留已重畫的底圖HD，交給生圖只重畫這些範圍。登錄時（`hd_picture_complete.py --patch-art`）每個畫格都是本次登錄的底圖HD，只在重畫範圍貼回生成結果，再往外2點漸變銜接，範圍外與底圖HD逐點相同；顏色與底圖相同的畫格直接用底圖HD。登錄時核對底圖HD的SHA與做參考圖時相同。

- `--check`對位：生圖常把面板內容整體挪動，`portrait-yuup-all`第三欄三格整欄左移約32點。以面板上未改動的底圖上下文（重畫範圍外再擴2點不計）找平均亮度差最小的位移，搜尋半徑48點，登錄沿用這個位移。
- `--check`一致性：重畫範圍每個色號的平均色，與同色號在整張底圖HD的平均色比較；底圖沒有的色號才比實機色盤色相。
- 上限依這批量測定：對位後上下文亮度差不超過12、漸變帶不超過20（對位後實測最高7.8與16.4，錯位一欄時為29到60、35到44）；色號平均距離不超過100、佔重畫範圍一成以上的色號不超過130（紅綠互換在177以上）。`seip`與`new1-talk`第2格的色號距離接近上限，原因是嘴內紅色在底圖裡對到披風的同色號，目視合成結果後接受。
- `--dump-set`的畫格取自實機截圖，登錄時另建`story-`群組；`--close yuu3-dark=6`先把重畫範圍閉合6點並補洞：原版主角以不變的黑點勾出身體，換色時只有黑點之間的色點改變，不納入黑點時底圖的紅衣綠褲會從縫隙露出。

## 合成成本

片頭與結局每次畫面改變都要重新比對整幅。補登錄後的第一版每次比對約0.4秒：兩色抖色片段在畫面上到處都對得上，每個巧合位置都完整掃描整張母圖；同一張母圖也在上百個錯位位置被當成局部母圖。現行做法：

- 先嚴格核對（第一個不同就停），完全相符的母圖不再找局部。
- 只有三色以上的片段拿來定位局部母圖。
- 抽樣最多512個特徵點，抽樣相符不到一半、或比目前最佳位置低0.1以上，不做完整核對。
- 每張母圖最多一個局部位置，取特徵點相符比例最高者。
- 放置範圍完全在畫布內時直接讀寫`Pix`；`TestCompletePaintDirectEquivalent`以三張實機截圖核對與原本`RGBAAt`／`SetRGBA`路徑整幅逐點相同。

`BenchmarkPictureCoverageDraw`以同一張實機截圖每次重新比對，`nostory`移除`story-`群組並關閉片頭模式，近似補登錄前；兩者在同一場景交錯執行。重畫並登錄後`story-`項目由1,762增為3,746，主機另有其他專案負載，7次中位數：片頭公主特寫9.2→11.9ms、片頭公主說話9.7→13.9ms、Ada洞窟6.9→8.6ms。遊戲中每次比對約多1.6ms。

## 色序

已證實，story圖集與完整插畫圖集的v1參考圖用了與實機不同的色序：實機片頭（62M）與結局（656M）在下列色號共用同一份色盤，v1參考圖則紅綠兩色版互換。

| 色號 | 實機 | v1參考圖 |
|---|---|---|
| 2、32 | (125,0,0) 暗紅 | (0,127,0) 暗綠 |
| 34 | (251,0,0) 紅 | (0,255,0) 綠 |
| 51（結局） | (251,0,251) 洋紅 | (0,255,255) 青 |
| 98 | (251,125,0) 橘 | (127,255,0) 黃綠 |

實機的低四位元順序是藍、紅、綠（1藍、2紅、4綠），與PC-98數位八色相同；v1參考圖用的是IBM的藍、綠、紅。三支來源工具（[hd_manual_sources.py](../../tools/hd_manual_sources.py)、[hd_manual_tail.py](../../tools/hd_manual_tail.py)、[hd_complete_sources.py](../../tools/hd_complete_sources.py)）的公式已改為PC-98色序，但沒有重跑；重畫的參考圖由`hd_picture_refs.py`另外產生。

公式色盤只是近似。片頭與結局四個場景（656M、1016M、386M、566M）、外框（1010M）與FIN（1286M）與公式逐色相同；人像、yuu3與魔王宣言另外載入場景色盤，例如68號在人像場景是黑色、公式是綠色，yuu3三張用64030色盤，剪影畫格用4370色盤；魔王宣言在實機是藍色線條、紅眼，v1依片頭第一幕的色盤畫成灰白色。因此參考圖一律以實機截圖的色盤為準。

## 未處理

- yuu3灰光剪影畫格在片尾六行捲字期間（1714M到1781M）仍顯示原版光路與剪影：捲字層依規格066以原版色盤重畫整個捲字視窗的底圖平面（色號與0x99），蓋過HD。新圖面在捲字結束後（1781.85M到1807M）顯示。要改須調整捲字層與規格066的契約。
- 1706.85M到1711.65M，主角跑進光裡時，規格066的溶解沿用把新增點少的變化判為清黑轉場，沿用之前的`yuu3-base`合成畫面，主角處露出原版點。插畫本身在1707.65M起已對上`yuu3-final`；重畫前的探針相同。
- `dmaou-cycle-all`：五個部件的色號（0、5、6、80、85、86、96、101、102）與實機宣言畫面不同，開機與片頭截圖都沒有出現。這輪依片頭第一幕色盤重畫成灰階，沒有實機證據，不計入完成。
- `credits-scroll`：96×265的公主全身捲動圖，人工圖格仍是v1色序。前88列就是`new1`，由整張插畫先畫；第96列以後在結局截圖中沒有找到，未經實機核對。
- `ttl1`、`ttl2`在開機、片頭與結局截圖都沒有出現，參考圖用修正後的公式色盤，未經實機核對。`nec`只換人工圖格，同樣用公式色盤。
