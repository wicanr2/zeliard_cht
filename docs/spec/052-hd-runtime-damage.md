# HD 效能與受傷顯示

狀態：限定CONFORMED。使用者回報 HD 移動較慢，受傷時整幅退回原貌。本輪修正顯示成本與受傷來源，並將怪物、魔王的文件縮圖加入私人 GitHub README。

## 範圍與證據

- 先以既有正常玩家來源測量 HD 合成成本，再修正熱點。不增加原版移動速度，不改計時、碰撞、生命值或存檔。
- 受傷來源先保留原版完成圖、主體記憶體與拒絕原因；只放行能獨立重建完整原版畫面的分支。不能沿用受傷前的舊畫面掩蓋缺口。
- 沿用已生成手繪圖面與原版透明遮罩。需要補的是未接通的受傷姿態或閃爍呈現，不另改畫風。
- 怪物與魔王總覽使用既有來源及已接入 HD 圖面，縮圖標明來源家族與抽樣範圍；不加入完整遊戲資料或原尺寸圖庫。

## 驗證與紀錄

工作區為 `workplace/hd-runtime-v1/`。保留修改前後相同來源、相同容器限制的效能數字及輸出雜湊。受傷以正常玩家路徑驗證，補上針對拒絕及遮擋的回歸檢查，不重跑通關。文件入口為本規格、CONTEXT、WORKLOG 與 VERIFICATION-MATRIX。

## READY 證據與實作契約

- 修改前的兩份正常洞窟來源交替繪製，補圖層連同原版三倍底圖約44.32ms／畫格。收據為baseline/benchmark.log及cpu.pprof；程式與原始RGBA保存在baseline。
- 正常冷F7讀取未改SAVEM1副本、下繩索及接觸敵人，五份完成來源皆被「unobserved combined shield profile」拒絕。probe/receipt.json保存來源雜湊、主體與完成時刻、正常鍵序與雙原版狀態核對，輸入檔與工具沿048的固定身份。
- 這五份來源0093=2、00E8=255、FF38=0、FF40=0，其他特殊profile皆0。沿[048既有consumer證據](048-cave-combined-profiles.md)，01B1段內3AAE..3ABB跳過後手、3B94..3BAB與3BE7..3BF0選受傷主體、3BFD..3C26跳過前手。裝備不改變這些E8分支。只新增上述單一持盾組合，不放寬多profile或攻擊組合。
- diagnostic overlay只移除這個組合的拒絕，沒有改模板或原版。candidate.log記錄五份224×144完成畫面皆零差，且fman-all組裝皆有72×72高清姿態。這是已證實的繪製來源與圖面接通，不推導受傷數值或無敵時間。
- 圖樣搜尋改用當次資源索引、兩byte前綴篩選及整數錨點。完整圖樣、透明遮罩、由大至小且穩定的順序、安全退回與原RGB合成不變；載入時預解色彩，避免每幀重做色彩模型轉換。

## 限定驗收與交付

- 同容器、兩核心限制、相同兩份移動畫面交替繪製：44.319ms→6.624ms，約6.7倍。兩份960×600完整RGBA與修改前相同。這是補圖層基準，不外推整個遊戲FPS或所有硬體。
- 五份受傷後特殊姿態的原版224×144畫面均零差；既有高清元件全部可組裝。三組合成未知分支仍以原守衛拒絕。正式程式沒有寫入原版RAM或修改遊戲規則。
- [正常操作檢查](../../tools/hd_runtime_smoke.py)由冷F7讀未改SAVEM1副本，走到繩索接敵。FF36=255變色及E8=255後續特殊姿態各擷取原貌／HD／HD返回，六張實際視窗。兩組切換的CPU步數、cycles、RAM、indexed與palette相同，HD返回576000像素相同，地形及主角HD均匹配。正常DOS退出0，USR內容及mtime不變；根端已目視。
- 第一份GUI腳本的ImageMagick RGB緩衝變數與既有導航迴圈變數重名，在入口取樣時停止。只修腳本變數，於相同容器重跑通過；失敗畫面與狀態保留，不算產品缺陷。
- v.0.4.1-20261021六包逐檔SHA、模式、原版資料及平台架構通過；Linux兩AppImage實際啟動、Windows兩ZIP以Wine輔助啟動，macOS兩ZIP核通用架構及.app權限／結構。收據為dist-all同版smoke/release-audit.json及SHA256SUMS.json。未做Windows／macOS真機、實體手把或通關。原v.0.4.0與影片保留，不覆寫。
- [圖庫製圖工具](../../tools/readme_creatures.py)輸出八組怪物及十組魔王／首領的原版、HD縮圖。README使用相對圖片路徑，可在私人GitHub首頁顯示；[來源清單](../images/creatures-provenance.json)保存原圖、選用版本、尺寸與SHA。完整圖庫仍留本機。
