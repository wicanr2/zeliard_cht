# 開局揭開、F7選單與結局的無閃爍呈現及補譯

狀態：1.0.7限定交付（`v.1.0.7-20261023`），2026-10-23。使用者在1.0.6推送後要求：結局的敘述、製作名單與版權要翻譯；開局逐格畫出兩側柱子與第一次進城堡時要處理；F7也要處理；中文出現後又變回英文要確定都處理好。並決定：版號另出1.0.7；結局以直接載入結局模組驗證；HUD場景名稱、Jashiin的房間與alma寶石一併改成「中文（English）」；製作名單的日籍人名查得到漢字就寫漢字。

## 開局兩側柱子

已證實：開局與F7讀檔後，ZELRES1第6項模組（payload `0xCEB5`，載在`01B1:6000`）逐格畫出兩側48像素寬的柱子。冷新局約47.93M到48.47M指令，先由上而下畫完左柱，再畫右柱；最後把兩側雕像眼睛共30點由暗色（色號24、27、29、43）換成亮色。1.0.6只在兩側全部吻合參考圖時才畫HD，揭開期間顯示原版。

另一個原因：邊框HD圖與城鎮圖組綁在同一個按需載入工作，條件是城鎮地圖已載入（`01B1:C002`在32到1024），柱子畫完時才成立。

修正：

- `hd.Frame.Draw`：兩側每一點都是尚未畫的色號0、參考色號與RGB，或眼睛暗色畫格（`frameEyes`）時，視為揭開中，只在已有像素的8×8格畫HD，其餘格維持黑色。其他色號或色盤不同仍整組退回。
- 城鎮與城堡HD的載入條件加上「選單模組已載在`6000`」，柱子開始畫之前就備妥。GUI的等待頁出現時機提早，次數不變。

## 第一次進城堡

已證實：冷新局進城堡時，原版先畫天空，再逐欄畫城牆，約0.15M指令。這段期間城鎮完成畫面還沒產生，HD層比對不到，顯示原版逐欄畫出的過程。

修正：`TownFrames`在城鎮繪製開始（`67D8`、`6852`、`68AC`）時若還沒有已驗完成畫面，記下開始步數；到完成點`68BA`或來源換掉才清除。這段期間HD模式沿用上一次合成的城鎮畫帶（`48..272×24..158`），完成後換成HD。上限1M指令；完成點被拒收後不再沿用，直到下一次成功收下，避免畫面凍結。原貌模式不受影響。

## F7讀檔選單

已證實：在城鎮按F7時，原版把選單模組載到`01B1:6000`暫時取代城鎮模組，其餘地圖與資源不變；城鎮來源守衛包含`6000`的程式，選單期間背景退回原版。在洞窟按F7時不換模組（`6000`仍是ZELRES2第0項洞窟模組），原版以`289A`把框下畫面存到`31B1`緩衝、直接在洞窟畫面上畫選單，關閉時以`28D9`還原；洞窟完成畫面不再更新，畫面又多了框，洞窟HD因此撤除。兩者由具名截圖附帶的`01B1`段記憶體確認。

修正：

- `TownFrames.PresentMenu`：選單模組在時，沿用最後一張已驗城鎮完成畫面。以完成畫面的模組區補回`6000..9FFF`後須通過同一個來源守衛，鏡頭與色盤相同；畫帶內與完成畫面不同的點取外接矩形當選單框，框內放回原版。
- `CaveFrames`另掛`289A`與`28D9`記錄已存未還原的方框（AL列、AH八點欄、CL列數、CH八點寬）。畫面與最後一張已驗完成畫面的差異全在這些方框內、色盤相同時，沿用完成畫面，差異的外接矩形放回原版；有任何差異在框外就照舊撤除。
- 選單文字照舊由選單標籤層畫中文。

## 結局觸發與驗證方式

已證實：城堡小屋模組`OMOYPRO.BIN`（SAR2第11項）在`A03D`檢查`DS:0049`，非零時載入`enddemo.bin`（SAR2第50項）到`6000`、依顯示卡載入`gd*.bin`、把`FF77`設為`FF`後跳入。

使用者選擇直接載入結局模組驗證。探針新增`poke 段:位移 值`，冷新局走到城堡亭台，進小屋前寫`01B1:0049=1`，之後只送原版按鍵，載入與執行都走原版程式。這是結構驗證，不是正常通關；`0049`在正常遊戲中的意義未查。

## 結局製作名單、登場魔物與版權

已證實：名單直譯器在`66CD`，指標`6965`由`66BF`設為`787E`（SAR2 `45DFA`），到`FF`（`462A6`）結束。

| 控制碼 | 作用 |
|---|---|
| `FB`+2 byte | 設列（低byte）與欄（高byte） |
| `FD`、`09` | 換列；跳到下一個4的倍數欄 |
| `FC` | 以逐點清除方式清y=140..199 |
| `FE` | 換下一張圖（`6820`表，七個處理常式） |
| `F8`+2 byte、`FA`+1 byte | 等待長度、打字間隔 |
| `F7`、`F9` | 等待 |

每字以`AH=7`（色號119）畫在x=欄×8、y=列×14+144，畫完在下一格畫游標方塊。共60個字段、868字。

新增`EndingCredits`：掛讀字`66DB`、畫字`673F`→`6744`、清框`67B5`→`67BA`、換圖`6815`→`6819`；以預期畫面逐點核對文字區，只容許目前游標格不同。中文依已畫字數逐字出現，從原版字段起點畫，不得碰到同列下一個字段或右緣。換圖時目前畫面還沒畫字（版權前的整幅清除）就以換圖後的文字區為新起點；已有字時只接受原樣或清成0。

## 結局插畫說話動畫

已證實：結局人物說話時，原版用`8x..Cx`在臉上貼小圖（最大約36×32）。完整插畫層只在整張逐點相符時覆繪，貼了小圖就比對不到，只剩局部碎片，畫面成為HD與原版交錯的格子。

修正：`CompleteArtwork`保留上一次比對到的大插畫（至少64×64）；同一位置只有八分之一以內的點不同時沿用整張HD，說話小圖不顯示。畫面換掉或逐點清除超過八分之一就停止。只在`FF77`非零（片頭／結局）時沿用：完整插畫登錄中另有`ckpd-backdrop`（224×72）與`ympd-mountains`（224×88）兩張遊戲過場背景，角色會在上面移動，沿用會把角色蓋掉。

結局對話畫面的兩個肖像框（外框為1像素寬的119色矩形，左`41,21..143,114`、右`177,21..279,114`，內部肖像96×88）若沒有整張肖像比對到或沿用，整框改顯示原版。公主在對話畫面的姿態沒有登錄HD，原本由其他圖組裡剛好同色的8×8小格拼成HD與原版交錯的格子；改後主角肖像維持HD、公主肖像整框原版。只在結局模組載入時套用。

## 探針判讀

1.0.6的「中文出現後又變回英文」只剩片頭故事的黑色陰影字。真因有兩層：可見判定只看原版底色與字色不同的空白點，畫面上同色就算可見；色號0的字形在黑色畫面上畫完與擦掉同色，追蹤不會結束，之後別的圖（例如開局柱子）畫到同一格就被誤判。本輪改為：

- 不追蹤色號0的字形。本作的黑字只用於陰影（與彩色本字成對，本字照常追蹤）與看不見的標記；數量記在每次執行的stdout。
- 字形要算看得見，同格須至少有一點原版底色不同於字色、且畫布照原版顯示；否則畫面上的字色是覆繪層的底色或筆畫。
- 新增`revealed`：覆繪層拒收已認領文字、把原版字形寫回畫面的點數；`revealed_visible`：寫回的點到下一個合成點仍照原版顯示的點數，直接對應「中文之後又變回英文」，也涵蓋探針不追蹤的5像素小字。
- 新增`hud_undrawn`：狀態列原版欄位完整、卻放不下而沒畫中文的欄數。
