# 原版RGB三倍畫面合成

狀態：限定CONFORMED，2026-10-20。實作前READY存於`workplace/prose-v1/rgb-ready-v1.json`。限既有320×200 RGB到三倍原貌底圖的等價加速，不改正式HD倍率、圖面、原版時間或輸入。

## 證據

- 主入口42bdeaf6、110來源及原版／執行器身份沿[029](029-runtime-audio.md)。音訊欠載仍是必須修正項，不把本項通過當完整音效完成。
- `workplace/prose-v1/audio-performance-v1/`在相同程式、cycles3000及正常冷啟動量測：無觀察600次原版run約0.60倍虛擬／實際速度，有觀察603次約0.47倍。capture-frames是下限，並非相同狀態；差異與限制在ERRATUM.json。
- `audio-profile-v1/`只透過Go來源覆寫加入runtime/pprof，不改正常路徑。600筆run、最終RAM與生成WAV和無觀察量測相同。7.37秒CPU取樣中，Draw累計2.56秒，SetRGBA累計1.51秒。共用主機耗時有變動，不把單次比例當穩定效能保證。
- 現行Draw對每個原版像素寫九次SetRGBA，色彩不混合、alpha固定255，原版畫帶左上為0,48。這是最近鄰複製；將第一列寫入後複製兩次可保存每個位元組。
- 洞窟呈現器只有載入洞窟HD時才建立，本次開場未建立。先前快照成本只是候選懷疑，不當成本次根因。CPU列函式時查無CaveFrames符號的工具失敗保留。

## 接入與閘門

1. 只替換Draw既有三倍RGB底圖迴圈，HD與中文的後續順序不變。既有cycles、RunCycles、Render、原版掛鉤及觀察內容保持。
2. 新增bitmap.DrawRGB3，只接受完整320×200×3 RGB、可容納960×600的RGBA目標區；輸入不符時不寫。實際前端固定畫布滿足條件，原有非320×200分支不改。
3. 第一個高清列以RGB複製三份並加alpha255，再複製至下一列及下兩列。尊重RGBA的Rect、Stride及非零原點，不改目標區外。
4. 以舊SetRGBA迴圈作獨立參考，核整幅標準畫布、非零原點及子圖Stride；拒絕輸入須原子不寫。另比較同機微型效能量測，數字只屬此環境。
5. 以正常視窗原生日誌、原版快照及完整源音訊比對；實際音效生命週期仍須正常退出。不得用頭部測試取代視窗，也不稱音效欠載已解決。

原版來源、CPU剖析與完整圖像只留本地；研究工具與現行收據入口見CONTEXT。
