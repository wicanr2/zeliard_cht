# HD閃回原貌與移動延遲

狀態：READY，2026-10-22，限完成來源一致、已驗居民對話遮擋及可信新主體的批次間隙。使用者提供第一洞窟平台站位交替HD／原貌、移動延遲及Muralla居民對話閃回原貌的畫面。只處理這些顯示與操作問題，不重開全遊戲逐幀或通關驗收。

已證實的程式事實：TownFrames遇`blocked`對話會清掉完成來源；主介面在使用完成呈現基底後，部分人工HD圖層仍讀即時raw及RGB。CaveFrames會複製完整1MiB以核對來源，未知完成來源目前清掉舊呈現。這些是待查根因線索，還不能直接稱為使用者畫面的唯一原因。

研究沿`workplace/runtime-controls-v1/`。先核既有正常來源及圖層順序，再訂出可保留完成圖的場景、相機、資源與對話遮擋條件。不能以無條件顯示舊圖掩蓋換場或遮住對話，也不能只提高CPU倍率當作延遲修正。後續以限定站位／對話及最小必要操作驗證，不將截圖當效能證據。

## 呈現契約

正常冷F7與既有居民鍵序補證：對話開始後，原版仍會到達68BA；TownFrames以一般城鎮完整圖核對時，在對話覆蓋的場景像素回報`original pixel mismatch 8 0`，清掉`complete`。已證實這會使首次保留成功的背景在後續進字時消失。既有`wipeSource`仍保存上一個通過完整來源及逐像素核對的背景，可用作居民對話候選；再次核對來源、相機、時間及框外每個像素後才呈現，不能將被文字覆蓋的68BA候選當成新完整背景。正常來源測試入口見[stable_presentation_test.go](../../internal/prototype/hd/stable_presentation_test.go)，失敗及修正收據沿同工作區`normal-dialogue-*.log`。

- 人工圖格、完整補圖與元件組裝一律使用本幀選出的原版完成圖及同一快照資源，不把即時raw混入完成圖的RGB底圖。過場專用層仍依057的即時原版來源處理。
- 已驗Muralla居民對話以TownDialogue的來源、原版程式及原生框幾何為依據。只在同場景、同相機／來源且對話框外的原生畫帶RGB及色號與完成圖相同時保留HD背景；所有HD層完成後，原生對話框含邊框／進字畫面放回最上層，再沿原中文層顯示。框外任一未知變動、換場或來源錯誤即拒絕，不能擋住對話。
- 4129的新可信主體可早於703C／7136批次開始。新增顯式HoldFreshBody選項，只在已驗程式／色盤、同地圖且新主體時序成立時保留上一完整viewport，直到下一完成來源。舊預設來源契約不改；沒有新主體的未知寫入、模態、換地圖或失敗完成仍撤除。
- 正式前端每兩次Update或33.33ms合成一次，期間重用已合成材質，輸入Update仍保持60次／秒。避免嚴格wall-clock間隔因少量排程誤差跳過整次Draw，目標為30次／秒。CPU在實際完整呈現之間共用額度，依33.33ms減上次合成與3ms餘裕，最高24ms；過載時最少保留4ms，避免一次載圖尖峰讓後續操作幾乎停住。倍率仍作上限及依負載調整，不承諾主機高載必達30fps。幀率只計實際完整合成，不將重畫同材質的Draw算成新幀。這是059的後續前端節奏調整，不修改原版存檔或記憶體規則。

驗證使用既有正常完成來源及新主體間隙、對話框局部變動／框外反例、切回原貌、未知來源及像素不回寫。新增呈現路徑與既有eager路徑分開標示；原版規則修改只沿060。GUI限定重現使用者回報，未到達的站位不稱已正常驗收。

限定正常操作入口為[hd_stability_smoke.py](../../tools/hd_stability_smoke.py)，沿既有F7、自建存檔及第一洞窟鍵序，在Docker內執行。原始素材唯讀，輸出另掛`/output`；不在主機執行。

平台站位的既有正常鍵序另由[來源連續性探針](../../tools/hd_platform_stability_probe.go)讀取包內SAVEM1副本，保留其前史未知身份。只作來源診斷，不代替實際視窗或幀率驗收。

限定結果：候選正常GUI的居民對話、洞窟站立與移動各66筆樣本維持HD；正常平台鍵序另有1250筆來源樣本、首次完成後缺失0及十個檢查點。後者只核來源，不是GUI影片。單核心限制下洞窟移動約19至21fps，穩定30fps未通過；目前只聲明來源穩定修正、合成節奏與CPU額度改善，不將使用者精確站位或全遊戲每幀列為已驗。
