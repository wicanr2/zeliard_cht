# 小屋石像與旅館圖像

狀態：小屋限定CONFORMED；旅館READY，正常到達及GUI仍待驗。沿[全遊戲HD](034-full-game-hd.md)補尚未覆蓋的美術，不改玩法、輸入、存檔或原版時序。

## 來源與限制

原版SAR2的記錄19為OMOYA.GRP，記錄24為INN.GRP。OMOYPRO的A239 descriptor為01 14及原始名稱，INNAPRO的A2E1為01 19及原始名稱，消費端皆為cs:010C。RLE解碼已與原版常式核對。不能把8×8圖塊字典直接排成完整場景，也不能由資源名稱推定目前可達。

前置研究先以正常長老場景核對共同繪製格式。96格來源在正常畫面的56,23起，各格8×8，12欄8列；重建索引表在原版KENJPRO模組有完整相同bytes。它是格式的正常對照，不取代民房或旅館的正常可達性。

Muralla現有自建存檔附近的住屋入口是已接HD的長老場景。此輪正常冷F7、Up取得home-normal-v1的完整RAM，7968個轉換bytes及6144個來源像素與KENJYA原圖相同，資料不注入。它不是OMOYA入口。後續核城堡原始C009入口表，C3CA為95、1，C3CD為52、0；不先由編號猜場景，正常走到世界位置760並Up後實際載入OMOYPRO，才確認小屋入口。小屋6480轉換bytes及17408像素與該正常來源完全相同。既有旅館探索未找到確認入口，不重掃同一道路，不猜服務標籤。原始來源、圖像及收據只留workplace。

## 接入閘門

來源、索引表、構圖與五張圖面已審，interior-layout-v2及interior-complete-v2保存來源與註冊，完整內建imagegen提示詞在interior-art-v1/generation-v2.json。石像初版雙手下垂，已另產生單手扶胸修正版，舊圖保留但不接入。四項測試、八個來源畫格的523836個合成像素、拒絕與缺圖整組退回、正常五點完整原版配對、vet及build通過。

GUI v1正常冷新局到城堡亭台，進小屋看石像、空白離開與原版退出0。小屋原圖及HD各156672像素與獨立PNG完全相同，兩組切回1152000遊戲區像素相同，根端已目視。此範圍升CONFORMED。旅館仍為七表項／四圖像的結構合成，正常到達、事件與GUI待驗，不借用小屋GUI代替。
