## 型別、狀態與失敗規則

1. 解碼輸入為完成來源、主角來源及原版色號。輸出為靜態底圖格、動態物件來源與像素、主角像素、武器像素。保留來源位址與兩個時間身份。
2. 順序為靜態底圖、動態物件、主角、武器。整個 224×144 色號必須與原版相同，否則原子拒絕。
3. 開始事件設定繪製中。完成事件成功後交換整組來源；主角來源缺失、未知裝備、越界、不同程式或色盤均撤除。
4. 繪製中保留上一完成來源。非繪製中若遊戲區與該來源不同，撤除。時間倒退、模態阻擋或場景更換也撤除。未有第一個完成來源時保留當次原貌。
5. 模態阻擋由前端傳入；來源守衛及區域差異檢查仍獨立存在。尚未驗的洞內選單不得稱已涵蓋。
6. `Present` 只交換遊戲區；色號與 RGB 同時交換。輸出不得回寫快照或原版。觀測狀態保存來源與當次時間差。

## 驗收與限制

- 內部驗證：真實畫格重建、錯誤來源與裝備拒絕、越界、RGB、模態與時間倒退撤除、批次保留、區外即時資訊、深複製。
- 原版驗證：固定首戰鍵序至少 25 點完整記憶體、暫存器、色號、色盤、時間、檔案與輸入相同。每次完成來源均須通過整區重建。
- 呈現驗證：正常入洞、交戰、拾取、跳蹲、回城及實際視窗。單元測試不取代 GUI。
- 目前 1082 個有限取樣為 957 當次完成、125 批次保留，無批次外失配。回城路徑一筆 199 像素改動按規則撤除；最後模組已變為城鎮。
- 存檔仍由原版處理；適配層無存檔資料。驗原件、自建存檔與 mtime 不變。
- 原版來源、圖面及收據只留 ignored workplace；自有程式與規格採 RRSAL-1.0。不產生 Release 或正式包。

本規格不代表中文、手把、音訊、全遊戲 HD 或跨平台交付完成。
