## 接入閘門

1. 核共用圖集載入位置及平台／其他必要圖格的消費端，保留原始函式名、位址、bytes與證據等級。
2. 依真實相鄰圖格準備手繪圖，保存完整提示詞、引用及產物SHA、尺寸、透明與接縫；現有Muralla入口圖保留其來源契約。
3. READY後才擴充來源守衛，不能把所有64以上ID通用放行。缺圖、資源或位置失配須原子退回。
4. 以正常平台上下移動、跳上／離開及捲動取得原版／覆繪完整狀態配對，再驗實際視窗與原貌切回。其他共用圖格按用途抽樣，不以單張圖集稱全洞窟完成。

正式封包及版本保持原身份。以下限定契約已具備來源及圖面，可以接入正式呈現器；未驗項不升CONFORMED。

## 前版候選與正常操作

`cave-common-registration-v1/manifest.json`保存三個24×24圖格及72×24前版候選。圖面直接從1254×1254生成原圖的主體裁切取樣，再以本平台的原版非零包絡裁切，框外寫入零像素。當時包絡1287個HD像素中有51個全透明像素；第二版已補齊，第一版保留歷史身份。

正常v3已站到平台中央、升起並走到右側通道。v4重播首個升起點，RAM／暫存器／色號／色盤／steps／cycles與v3相同，再正常Down、Up，原版C004表第一項列值17→24→17，兩張升起原圖相同。這只是原版正常操作與來源證據，未接HD或GUI，不宣稱所有原版狀態的配對。

## 限定驗收

收尾入口為 `workplace/full-hd-v1/cave-platform-final-audit-v1.json`，由[平台稽核](../../tools/hd_cave_platform_audit.py)重生至新檔。[圖面與拒絕測試](../../internal/prototype/hd/cave_common_test.go)核五個正常點6435個高清像素、完整來源不變、缺圖及九種來源失配原子拒絕；另以結構邊界驗左右部分裁切仍須核畫面外完整三格，不把它稱正常捲動到達。

[正常配對](../../tools/verify_cave_platform.sh)十點完整原版狀態與存檔不變，十一組地形共存；28項圖面回歸、一項邊界測試、三項正常／來源測試、vet及build通過。實際視窗 `cave-platform-gui-v3/`四組原貌切回2304000遊戲區像素相同，5148高清像素獨立相同；正常跳上、升降、再升及離開，DOS退出0、存檔bytes及mtime不變，根端已目視。GUI v1的座標基準混用與v2的PageUp／數字鍵盤9誤配保留為測試腳本失敗，未改產品或原版規則。

正常呈現仍有42次繪製中來源拒絕，SAVEM1路徑另有18個未匹配主角畫格與十個可見武器來源鍵，均保留收據。這些缺口與其他共用圖格、城鎮及後段正常路徑仍阻止全遊戲HD完成，封包未更新。
