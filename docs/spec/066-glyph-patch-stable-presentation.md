# 原版字形改寫與無閃爍呈現

狀態：1.0.6限定交付（`v.1.0.6-20261023`），2026-10-23；規格起草於2026-10-22。使用者要求兩件事一併交付1.0.6：Windows啟動失敗修正，以及徹底解決閃爍。閃爍的驗收由使用者限定為兩條：HD模式依目前模式決定畫HD或原貌，同一內容不在兩者之間交替；英文不得先出現再變中文。使用者選擇另存patch版檔案，原版不畫、由前端繪製，原始檔案不覆寫。

## Windows啟動

已證實：1.0.5以`filepath.Rel`判斷使用者目錄是否位於原版目錄內。Windows上兩者位於不同磁碟區時`Rel`回傳錯誤，程式把錯誤當成位於目錄內而拒絕啟動。Wine重現：遊戲在Z:、預設使用者目錄在C:時出現與使用者截圖相同的訊息。

修正改以檔案身份逐層比對祖先目錄（`os.SameFile`），另解析最深既有祖先的連結。啟動成功與失敗都把兩條實際路徑寫入`startup.log`。使用者回報遊戲在C槽，該案例的真因未重現；1.0.6的日誌可據以確認，不宣稱已修好該台電腦。

## 閃爍真因

前端每次合成都從原版畫面或完成快照開始，各HD層與中文層各自比對來源，比對成功才覆繪。畫面上不是原版與HD兩個畫家輪流畫同一面螢幕；露出原版的畫格，是某一層在該次合成判斷不了而退回原版像素。城鎮對話在`64B2`至`64B7`的每個字形與捲動期間設定pending，`Draw`回傳false，當次合成就露出原版英文。

基線（1.0.5 CHT-HD資料、11條既有正常鍵序、切片20000指令）：

| 類別 | 結果 |
|---|---|
| 城鎮對話`64B7` | 居民路徑1652字、教堂108字先露英文再換中文；同一來源中文層中斷25次 |
| 國王與商店對話`7120` | 每條1至5字；中文層中斷約4個合成點 |
| 裝備頁`AA44`／`AA4F` | 4至12字 |
| HD單一合成點交替 | 國王16次、教堂37次、長老12次 |
| HD較長交替 | 道具店肖像74次（中位數26、最長187）；居民對話期間城鎮各層15至17次（中位數約35） |

道具店肖像只比對`56,23`至`152,87`，不與對話框重疊；交替來自店主說話動畫不在已登錄四姿態。輸出在`workplace/release-v106/probe/out/baseline-*`。

## 量測

`cmd/zeliard-preview`的`-flicker-probe`以固定指令數切片重播既有鍵序，每片走與GUI相同的`compose`，記錄各層是否覆繪，以及每個`27E9`字形在畫面上露出、被中文層蓋住或被HD層蓋住的合成點數。不開視窗、不用實際時間，同一輸入結果相同。`tools/flicker_report.py`計算：

- 英文先露出、之後被中文層蓋住的字形數。
- 同場景內各層「有、無、有」的中斷次數與長度。

切片20000指令時，GUI的任何呈現點都落在兩個切片點之間；探針的每一列都是玩家可能看到的狀態。

字形判定（r24起）：

- 字形剩不到一半的點才停止追蹤。下一字的陰影會蓋到前一字邊緣，片頭轉場也逐點清字；任一點被改寫就停止，會漏掉仍看得到的殘字。
- 字形點的3×3塊與字色相同，但同一8×8格的空白點也呈現字色，或現存字形點只有不到一半可見時，畫面上是同色的中文粗筆畫或保留的數字圖形，記為`coincident`，不算英文可見。真正露出的英文整個字都看得到。
- 色號0的字形是黑色陰影，畫在黑底上看不到，報表另列。
- 英文分兩類統計：中文之前先露出，以及中文出現之後又露出（退回）。
- `-flicker-shots`截圖時另存同一合成點的守衛色號與色盤（`.indexed`，64000 bytes加768 bytes），供逐點判讀轉場。

## patch版驅動

| 位址 | 原bytes | 新bytes | 說明 |
|---|---|---|---|
| `2832`，3 bytes | `b8 00 a0` | `a1 c9 2c` | 八乘八字形；位於`27E9`的`push cs; pop ds`之後 |
| `22FE`，3 bytes | `b8 00 a0` | `a1 c9 2c` | 小字；常式本身以DS讀`F504`字型與`2CBD`色號，DS必為`01B1` |
| `2333`，3 bytes | `b8 00 a0` | `a1 c9 2c` | 小字標題路徑 |
| 檔尾`2CC9` | 無 | `00 a0` | 目的段變數，預設`A000` |

只把`mov ax,0A000h`換成`mov ax,[2CC9]`。指令數、DOSBox週期（每指令1）與`AX`都與原版相同。前一版把兩條指令合成一條，差分測試在第5267萬步出現CS:IP分岔，已改用此版。

前端在啟動時從原版目錄讀`GMMCGA.BIN`、核SHA與每處原bytes後產生patch版，寫入使用者可寫層；dosgolem開檔時可寫層優先。原版目錄、原始檔與Git都不含patch版。變數維持`A000`時應與原版逐指令等價，以差分測試證明。

## 字形閘與虛擬平面

覆繪層在原版呼叫字形常式前已核對來源（城鎮`64B2`、國王與商店`711B`、選單`22DB`等）。只有已認領且有譯文的文字，前端在`2832`、`22FE`、`2333`執行前把變數改成`B000`。真VGA在mode 13h不解碼`B000`，dosgolem把它當一般RAM，寫入不會顯示。未認領文字照原版畫英文，之後不會被中文取代。

被壓下的字形由原版自己寫到`B000`；前端監看這段寫入，照實際值放進虛擬平面。VRAM任一寫入清除平面對應點；`2857`捲動時目的點取下一列，`289A`存框時記下對應平面值，`28D9`還原時取回。dosgolem的`WatchWritesAt`只在值改變時通知，會漏掉以底色清框，所以另以[通用寫入監看差異](../../tools/dosgolem-write-watch.patch)開放既有的每次寫入監看，不含Zeliard條件。所有HD層與中文層吃「VRAM疊上平面」的等同原版畫面，判斷邏輯不變。合成最後一步把畫布上原樣露出的平面像素換回VRAM像素，英文因此只存在守衛輸入。

## 刻意不照做

使用者選「字形不寫VRAM」。實作把字形寫到不顯示的`B000`段，畫面結果相同。驅動仍完整執行，以免前端得重寫每個依原版字形判斷標籤是否被擦除的守衛。

## 驗收

1. 差分測試：原版與patch版同步跑既有正常鍵序。每個切片點，「VRAM疊上平面」等於原版VRAM；RAM排除`B0000..BFFFF`、驅動patch範圍與`31B1`方框緩衝的重建差異後完全相同。

## 差分結果

`tools/glyph_patch_diff.go`在原版與patch版兩台dosgolem同步執行，patch版掛真實城鎮與對話覆繪層。居民路徑2.85億步、14419個比對點：步數、週期與CS:IP全程一致，壓下4928字。剩餘差異只有一類：壓下期間`AX=B000`，中斷處理推入堆疊或返回後殘留，原版為`A0`、patch版為`B0`；已認領的呼叫端（`64B7`、`7120`、`6336`、`6346`、`6AE3`、`6AEF`）返回後都`pop ax`，不外流。工具只接受這種byte差異且位於SS:SP上下512 bytes內，其他差異一律失敗。武器店、洞窟平台、道具店、教堂、長老路徑均通過。

## 片頭捲字溶解

首章捲字的字層在調色盤位元66h、底圖在99h。片頭溶解逐點清掉整個畫面，原本整層中文因「未觀察的寫入」退出，約2.2M指令露出溶解中的英文。捲字守衛改為只比對66h字層，底圖取當下畫面；被清掉的英文點只計數，中文依剩餘比例以原版像素位置抖動同步淡出。探針中斷由110個合成點降為7個，期間畫面全黑。

## 轉場逐點清黑

片頭故事期間按Space，以及離開道具店與長老房間時，原版約以1.2M至2.1M指令（1x速度每秒約3M指令，約0.4至0.7秒）把整個畫面逐點清成0；其他房間的離場未逐一截圖。截圖保存的色號證實這段只有「非0變0」的寫入；片頭清黑開始的同一段另有最後一個打字字形的18點新增。

清黑一開始，各覆繪層因畫面改變而撤除：HD插畫先變成HD與原圖交錯，人像外框被清後退回原貌，對話層則把壓下的英文寫回VRAM。結果是中文與HD消失，原版插畫、人像與英文隨清黑露出到畫面全黑為止。片頭的「Once, long ago, a ter」、道具店的「Thank you, sir. Please come again.」、長老的「The Spirits are with you.」都有截圖。

處理（`cmd/zeliard-preview/dissolve_hold.go`）：

| 條件 | 片頭（FF77非0） | 房間 |
|---|---|---|
| 保存 | 有任何覆繪層的合成畫面 | 房間模組已載入、城鎮與洞窟畫面都不在 |
| 介入 | 同場景、同色盤；相對保存畫面有清成0的點，新增不超過256點且少於清除數的一半 | 同上，但不容許任何新增；第一次介入時須有人像框內部以外的清除 |
| 排除 | 捲字層有作用時不介入，捲字自行處理只清字層的溶解 | 只清人像框內部的點（人像動畫）不算轉場開始 |

介入期間改畫保存的合成畫面：原版已清成0的點塗黑；原本就是0的點（黑底上的中文與高清細節）依剩餘比例，以原版像素位置抖動同步消失。片頭故事列與房間對話框內用整區比例，因為中文排版與原版英文位置不同，所以只清對話框時舊中文會一起消失。其餘以8×8格計算，原版整格為0的格子沿用保存畫面，全部清完才塗黑，所以局部清除不會在框外的高清細節上留下黑點。出現其他改寫、換場景、換色盤或全部清完就停止，回到一般合成。

房間內句子之間清框或游標擦除也會短暫介入。期間只有清除、沒有新增，呈現的是清掉的框與保存的其餘畫面；下一個字形寫入即停止。CHT版沒有城鎮完成畫面，從城堡外進國王房間時房間模組已先載入，原版的清黑轉場也會介入（國王二訪約65個合成點）；截圖確認畫面與原版清黑相同，狀態列中文保留。

成本：保存一張合成畫面約1.07毫秒，一次溶解約2.28毫秒（Intel Core Ultra 7 165U，容器限一顆CPU，基準程式與結果在`workplace/release-v106/bench/`）。片頭與房間每次合成最多做其中一項；對實際幀率的影響未量測。

單元測試在`dissolve_hold_test.go`：逐點清除、整區一次清空不殘留、新增過多與捲動式改寫不介入、房間不容許新增、清框後框內不殘留舊中文且框外不塗黑、人像框內清除不觸發。
