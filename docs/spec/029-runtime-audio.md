# 原版串流音訊輸出

狀態：限定CONFORMED，2026-10-20。格式、單向隔離、播放生命週期及虛擬裝置輸出已驗；穩定節奏、人耳及實體裝置尚未完成。實作前READY另存`workplace/prose-v1/audio-output-ready-v1.json`。

## 範圍與證據

- 原版仍由dosgolem執行。音源使用同一個`oracle.Audio.Render()`，不替換音樂、不改遊戲速度、時鐘、輸入或存檔。
- 開工時主入口`01da4dfb`、104份來源，Git `8bafe4a`。固定882份dosgolem來源與原版29檔沿CONTEXT清單；原版與參考專案唯讀。
- 固定執行器`workplace/dosgolem-source/oracle/live.go`的`Render()`回傳44,100 Hz單聲道`int16`取樣，時間來自既有DOSBox相容cycles。它也消化埠紀錄，不能在音效執行緒重複呼叫。
- 現行`cmd/zeliard-preview/main.go`在每次`RunCycles()`後呼叫`Render()`並丟棄回傳值。
- 本地Ebitengine v2.9.9的`audio/audio.go`規定`NewPlayerF32`接收無檔頭、32位元小端浮點雙聲道PCM，並推薦新程式採此介面。來源是[固定版本的官方原始碼](https://github.com/hajimehoshi/ebiten/blob/v2.9.9/audio/audio.go)。參考`psychic-war/cmd/psychicwar/main.go`的串流分層，不沿用其速度檔位、取樣裁切或測試狀態還原。
- 研究入口：`workplace/prose-v1/audio-output-source-v1/`與同層的音訊探針。每份收據記原版、執行器、輸入日誌、程式與PCM雜湊。

## 已核原版

`audio_output_probe_v1.go`重播028成功視窗日誌的698筆冷開機前綴，停在原版32M步之後的自然放鍵點。34,825,129 cycles以每毫秒3000 cycles換算，得到511,929個44,100 Hz取樣；API結果與整數公式相同。18,610個非零取樣，峰值8192。`audio-output-source-v1/receipt.json`、`original-mono.pcm`及`original-mono.wav`保存逐段時鐘、原版暫存器比對、SHA-256與限制。原版未寫檔，未還原或注入狀態。

這只證明所列開場訊號可供輸出，不證明全遊戲音樂、物理喇叭或聽感已驗。

## 接入契約

1. 正常冷開機鍵序的非靜音取樣及雜湊為實際輸入基準。後端以44100 Hz工作，將每個`int16`除以32768轉成`float32`並複製至左右聲道，這是格式轉換，不新增音量處理。
2. 原版音訊只由前端更新執行緒取得，播放執行緒只讀獨立緩衝。
3. 增加可撤回的`-audio off|ebiten`雛形參數，預設仍為off；不增加正式工具列或持久設定。正式預設與音量介面留待確認。`-audio-wav`僅供本地保存原版產生的單聲道PCM，使用新檔，不覆寫已有檔案。
4. 緩衝最多4410個單聲道音框，約100毫秒；後端請求50毫秒緩衝。欠載補零並計數，滿載丟最舊取樣並計數，不等待緩衝空間。保持任意長度`Read`的雙聲道音框順序。裝置執行緒不讀原版、不寫檔。
5. 暫停、失焦、手把設定頁、擷取收尾與結束時，關閉當次播放器與來源，丟棄前端排隊資料。恢復時建立新的來源與播放器，不重播舊佇列。已交給裝置的資料依後端延遲排空，不宣稱物理裝置立即靜音。
6. 播放開關的原版RAM、暫存器、VGA、色盤、時間、等價輸入與存檔相同。排除裝置回呼改動原版的可能。保留現有每次更新的cycle預算，本輪不調整遊戲速度。
7. 區分輸出格式、後端接收、實際聽感與硬體驗收。使用現有`eob-audio-capture:20261009-r3`的獨立PulseAudio虛擬輸出及監聽錄音；不借用其他專案的容器、資料或主機憑證。虛擬輸出不當作實體喇叭驗收。
8. 若目前負載導致欠載，記錄數量與播放限制，不插入額外原版執行、不改取樣率或隱藏丟樣。穩定節奏與人耳確認保留為整體目標的待辦，不以格式通過冒稱完整音效。

本項沿既有硬體規格近似，不宣稱原版逐週期或逐波形一致。正式音訊預設、平台與速度驗收仍依專案決策；不重開DAC／PIT／ISR逆向。
